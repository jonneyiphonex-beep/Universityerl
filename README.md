# Universityerl

نظام أولي قابل للتشغيل لإدارة الهيكل الأكاديمي متعدد المناطق، بخادم Erlang/OTP وواجهة عربية متصلة به.

## المتطلبات والتشغيل

- Erlang/OTP 25 أو أحدث
- `rebar3`

من مجلد المشروع:

```sh
rebar3 compile
rebar3 shell
```

داخل صدفة Erlang شغّل التطبيق:

```erlang
application:ensure_all_started(universityerl).
```

افتح `http://127.0.0.1:8080`. يستمع الخادم على loopback فقط افتراضيًا. غيّر المنفذ عبر `UNIVERSITYERL_PORT` وعنوان الربط عبر `UNIVERSITYERL_BIND` ومجلد البيانات الدائمة عبر `UNIVERSITYERL_DATA_DIR`. داخل Docker، اضبط الربط إلى `0.0.0.0` مع نشر المنفذ إلى المضيف. لا تستخدم هذا العنوان على خادم مكشوف دون إضافة المصادقة وHTTPS. يجب تشغيل الخادم من مجلد المشروع كي يجد ملفات `web/`، أو ضبط `UNIVERSITYERL_WEB_DIR` لمسارها.

عند أول تشغيل تُنشأ قاعدة Mnesia محلية في `data/mnesia` وتُضاف بيانات أكاديمية تجريبية بسيطة. لا تحذف هذا المجلد إذا أردت الاحتفاظ ببياناتك.

## الوظائف وواجهة API

تدير الواجهة الوحدات من المنطقة إلى البرنامج: بحث وتصفية وإضافة وتعديل وحذف وتصدير CSV، مع سجل نشاط. تحفظ العمليات في Mnesia، وتتحقق الخدمة من أنواع الوحدات والأب الأعلى النشط وتفرّد الرمز ضمن المستوى الأب نفسه، وتمنع حذف وحدة لها أبناء. عند تعذر API تستخدم الواجهة بيانات المتصفح التجريبية وتوضح حالة الاتصال.

- `GET /api/health`: صحة الخدمة ومؤشرات وقت التشغيل المتاحة من Erlang VM.
- `GET /api/units` و`GET /api/units/:id`: قراءة الهيكل.
- `POST /api/units`: إنشاء وحدة.
- `PUT /api/units/:id`: تعديل وحدة دون تغيير نوعها.
- `DELETE /api/units/:id`: حذف وحدة بلا وحدات تابعة.
- `GET /api/activity`: أحدث تغييرات الهيكل.

يشترط إرسال JSON بمفاتيح `type`, `code`, `name`, `parentId`, و`status`، وتكون قيمة `parentId` فارغة للمنطقة. الأنواع: `region`, `campus`, `college`, `department`, `program`؛ والحالات: `active`, `inactive`.

## الاختبارات والحدود

```sh
rebar3 eunit
```

هذه نسخة تأسيسية عملية تركز على API الهيكل الأكاديمي. مخطط `priv/schema.sql` يصف مجالات جامعية إضافية مثل الطلاب والمقررات والتسجيل، لكنها لم تُنفذ بعد كتدفقات API. لا توجد مصادقة مستخدمين أو صلاحيات أو HTTPS في هذه النسخة؛ لذلك أبقِ الخدمة على loopback ولا تعرضها للشبكة أو للإنتاج قبل إضافة المصادقة والتفويض والنسخ الاحتياطي. Mnesia هنا قاعدة أحادية العقدة، وليست بديلًا عن تصميم قاعدة بيانات موزعة أو خطة تعافٍ.
